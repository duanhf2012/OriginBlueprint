# 工作区节点定义加载设计

日期：2026-08-22

状态：已实现并通过 Go、前端测试和生产构建验证

## 1. 背景

OriginBlueprint 已支持通过 `nodes/*.json` 定义自定义节点，编辑器和 Go 执行引擎也可以使用同一份节点 schema。当前桌面端加载节点定义时只扫描以下来源：

1. 程序内嵌节点定义；
2. 可执行文件同级的 `nodes` 目录；
3. 当前工作目录下的 `nodes` 目录。

打开项目工作区并不会把 `<workspaceRoot>/nodes` 加入节点来源。编辑器的节点库加载和 `target.go` 的 F5 校验又分别调用现有的无工作区加载入口，因此用户即使按项目约定把节点 JSON 放在工作区内，也可能出现节点库不可见、重启目录不同导致结果变化，或者编辑器与执行校验使用的节点集合不一致。

OriginGame 的机器人自动化测试需要把节点契约、蓝图和函数文件作为同一个可版本管理的 E2E 工作区保存，因此必须先补齐工作区节点加载能力。该能力属于编辑器资源发现和校验一致性修复，不改变蓝图 VM、文件格式或节点运行实现。

## 2. 目标

1. 打开或切换工作区后，自动加载 `<workspaceRoot>/nodes` 下的节点 JSON。
2. 编辑器节点库、图加载诊断和 `target.go` F5 校验使用相同的节点来源、覆盖顺序和错误信息。
3. 保留现有程序同级目录和当前工作目录的扩展方式，避免破坏已有使用方式。
4. 节点来源顺序确定、目录去重，异步切换工作区时旧结果不能覆盖新工作区结果。
5. 工作区只提供声明式 JSON schema；Go 节点实现继续由宿主程序显式注册，不从工作区动态加载代码。

## 3. 非目标

- 不修改 `.obp`、`.obpf`、`.vgf` 的文件结构和兼容策略。
- 不修改 Go 蓝图 VM、编译结果共享、实例状态或异步 continuation 语义。
- 不通过 `os.Chdir` 改变进程当前目录。
- 不递归扫描整个工作区寻找任意 `nodes` 目录，只认工作区根目录直属的 `nodes`。
- 不允许节点 JSON 指定或加载 DLL、Go plugin、脚本等可执行代码。
- 不为本次能力增加节点包管理、远程下载、版本解析或依赖安装机制。
- 不改变浏览器模式只能使用其已有可用节点清单的边界。

## 4. 节点来源与覆盖顺序

桌面端按以下顺序合并节点文档，后加载来源覆盖前面相同逻辑路径的文档：

1. 程序内嵌节点定义；
2. 可执行文件同级 `nodes`；
3. 进程当前工作目录下的 `nodes`；
4. 当前工作区根目录下的 `nodes`。

工作区节点具有最高优先级，允许项目针对宿主已经注册的自定义节点提供自己的分类、标题、端口和默认值描述。内嵌节点仍是最低层稳定基线。

文件覆盖键继续使用相对于节点目录的规范化路径，不按操作系统绝对路径比较。例如两个来源都包含 `nodes/robot/login.json` 时，工作区版本覆盖当前工作目录版本。不同相对路径中的节点仍交由现有 schema 校验和节点类型冲突规则处理，不在资源发现层猜测合并。

目录在扫描前转换为清理后的绝对路径，并按 Windows 大小写不敏感、其他平台大小写敏感的文件系统语义去重。若工作区根目录就是当前工作目录，同一个 `nodes` 目录只扫描一次，但仍视为最高优先级来源。

空工作区表示不追加工作区来源。传入非空但不存在、不是目录或无法规范化的工作区路径时，工作区加载入口返回明确诊断，不能静默退回全局来源后让编辑器显示一套不完整节点。

## 5. 后端 API

新增工作区感知入口，返回结构沿用现有节点文档加载结果：

```go
func (a *App) LoadNodeSchemaDocumentsForWorkspace(workspaceRoot string) NodeSchemaLoadResult
```

现有入口保留，作为不带工作区来源的兼容调用：

```go
func (a *App) LoadNodeSchemaDocuments() NodeSchemaLoadResult
```

内部使用一个共享的来源解析函数：

```go
func runtimeNodeDirectoriesForWorkspace(workspaceRoot string) ([]string, error)
```

节点文件枚举、相对路径生成、覆盖合并和 JSON 读取仍只有一套实现。不得在 Wails API、引擎校验和测试中分别复制目录拼接规则。

工作区路径由桌面端当前已打开项目传入；后端不读取隐藏全局“当前工作区”状态，以避免并发校验、测试和未来多窗口共享可变状态。

## 6. 前端加载与工作区切换

前端平台抽象的节点加载方法增加可选工作区参数：

```ts
loadNodeSchemas(workspaceRoot?: string): Promise<NodeSchemaLoadResult>
```

桌面实现有工作区时调用 `LoadNodeSchemaDocumentsForWorkspace`，无工作区时仍可调用原兼容入口。浏览器实现保持当前内嵌清单行为，并忽略空工作区参数。

以下时机重新加载节点定义：

- 应用首次初始化；
- 成功打开工作区；
- 切换到另一个工作区；
- 用户执行现有“刷新节点”操作。

工作区文件浏览器的周期刷新不自动重载节点，避免每次轮询都重新解析全部 schema 和重建节点库。用户修改 `nodes/*.json` 后通过“刷新节点”显式生效。

加载请求携带单调递增的 generation，或者在结果提交前比较发起请求时的规范化工作区根目录与当前根目录。若用户快速切换工作区，较早请求即使较晚返回，也必须丢弃，不能覆盖当前工作区的节点库和诊断。

工作区加载失败时保留最后一次成功的节点库还是清空，继续遵循现有节点刷新失败策略；但界面必须显示本次失败和对应工作区路径，不能把失败结果标记为刷新成功。

## 7. `target.go` 校验一致性

`validateGraphWithEngine` 已接收 `workspaceRoot`。实现改为通过与编辑器相同的工作区感知加载函数取得节点定义，再为校验过程注册 dummy factory。这样工作区自定义节点可以参与编译期端口、类型、入口和依赖闭包校验，而不需要在编辑器进程中执行真实机器人网络逻辑。

校验必须遵守以下规则：

- 节点来源与第 4 节完全一致；
- schema 加载错误先作为校验错误返回，不继续用残缺节点集合编译；
- 函数蓝图依赖解析仍使用现有工作区 `functions` 规则，不因节点目录支持而改变；
- dummy factory 只用于结构校验，不代表宿主运行时已经注册真实实现；
- 校验成功信息不得宣称工作区节点在任意宿主中可执行，只能说明图结构对当前 schema 有效。

## 8. 安全与边界

工作区节点目录只包含声明式 JSON。资源加载器不得解释 JSON 中的本地代码路径，不得搜索系统 PATH，也不得根据节点类名反射加载实现。

OriginGame 等宿主必须在进程启动阶段显式调用 `Blueprint.Setup` 并注册每个机器人节点工厂。工作区 schema 与宿主工厂的节点类型和端口契约不一致时，应在宿主加载或图编译阶段失败，而不是运行中自动补齐。

错误信息可以包含节点 JSON 的规范化文件路径和字段位置，但不得读取或输出工作区外无关文件内容。符号链接和目录遍历继续服从现有节点目录文件枚举边界；相对文件键必须由已确认位于节点根目录内的文件生成。

## 9. 兼容性

- 不带工作区调用时，行为与当前版本一致。
- 现有放在程序同级或当前工作目录 `nodes` 中的扩展继续生效。
- 工作区来源只在实际打开工作区时追加，并以更高优先级覆盖同路径文档。
- 蓝图和函数文件无需迁移，保存结果不因节点来源变化而自动改写。
- Wails 新绑定生成后保留旧方法，已有前端或外部调用不会因签名替换而失效。

## 10. 测试

后端至少覆盖：

1. 无工作区时保持原来源集合；
2. 工作区 `nodes` 能被加载；
3. 内嵌、程序目录、当前目录、工作区的覆盖顺序确定；
4. 工作区与当前目录相同时只扫描一次；
5. 非法或不存在的非空工作区返回诊断；
6. 工作区自定义节点可通过 `target.go` 结构校验；
7. 工作区 schema 错误不会被残缺集合掩盖；
8. 函数依赖校验行为不变。

前端至少覆盖：

1. 打开和切换工作区会带正确根目录刷新节点；
2. 快速切换时旧异步结果不会覆盖新工作区；
3. 文件浏览器周期刷新不会触发节点重载；
4. 手动刷新能加载刚修改的工作区节点并展示诊断。

实现完成后执行 Go 测试、前端单元测试、生产构建，并使用一个最小工作区完成桌面端人工验证：打开工作区后节点库可见自定义节点，创建连线后 F5 校验成功；破坏端口定义后节点刷新和 F5 均报告同一来源文件的错误。
