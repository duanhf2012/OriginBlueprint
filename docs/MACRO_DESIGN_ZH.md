# 蓝图宏（Macro）设计文档

> 版本：1.1
> 状态：已实现（含入口合并、校验兜底、来源注释框等后续增强；详见 5.2 改动清单）

## 1. 概述

**宏 = 复制语义的可复用逻辑块。** 把一段从入口节点开始的完整蓝图逻辑保存为独立的 `.obpm` 文件，在其他蓝图中一键整块复制插入；插入后与源文件互不影响、各自演化。

解决的核心问题：**多个业务（如多种 buff/技能）共用同一套逻辑起点，但之后需要各自微调**——引用式的复用（函数）会让改动传播到所有使用处，不适配这种"起点相同、终点不同"的场景。

## 2. 背景与调研

### 2.1 虚幻引擎宏的对照

| | UE 蓝图宏（宏库） | OriginBlueprint 宏 |
|---|---|---|
| 存放 | 专用宏库资产 | `.obpm` 文件（工作区任意目录，约定 `vgf/macros/`） |
| 放入目标图 | 编辑期为引用节点，**编译期内联展开** | **插入时物理复制**（节点连线直接铺进画布） |
| 源头改动 | 重编译时传播到所有使用处 | **永不传播**（插入即分叉） |
| 变量 | 跨图复制节点时引用会断 | **智能合并**：同名同类型复用、缺失自动补建 |
| 格式差异 | 宏是独立资产类型 | **零格式差异**（.obpm 内容 = GraphDocument） |

采用"插入即复制"而非 UE 的"编译期展开"，原因：目标是策划工具的"起点相同、各自演化"工作流；复制语义不需要任何引擎/编译期支持，纯编辑器功能，风险最小。

### 2.2 与函数的分工

| | 宏 `.obpm` | 函数 `.obpf` |
|---|---|---|
| 复用语义 | **复制**（插入后独立演化） | **引用**（改一处全生效） |
| 运行时 | 普通节点，无任何特殊处理 | 独立编译单元，调用语义 |
| 内容起点 | 入口节点开始的完整逻辑（可多入口） | 签名 + 入口/返回节点 |
| 适合 | 多业务共用逻辑起点、之后各自改 | 统一维护的公共逻辑 |

**选型口诀：要"各自改"用宏，要"全生效"用函数。**

## 3. 关键设计决策

### 3.1 扩展名 `.obpm`：纯身份标签

- **格式与 `.obp` 完全一致**（同一 GraphDocument 契约），扩展名只承担"身份识别"职责；
- 家族对称：`.obp` 图 / `.obpf` 函数（f）/ `.obpm` 宏（m）/ `.obproj` 工程，字母序自然聚簇；
- 身份标签的收益：模块库归类、右键菜单识别、文件对话框筛选，都不依赖文件所在目录；
- 无主流软件占用该扩展名。
- 曾考虑并否决的方案：仅靠目录约定（无法支撑"不依赖位置的识别"）、`.obm`（丢失家族词干）、为新格式发明元数据（当前没有格式差异，拒绝过度设计）。

### 3.2 复制时的合并规则

| 内容 | 规则 |
|---|---|
| 节点 | 全部复制，ID 重新生成；函数终端类节点按既有防重规则过滤 |
| 连线 | 随节点重映射后重建 |
| 变量 | **同名同类型 → 复用目标图已有定义**（连线自动指向）；目标图没有 → 按源定义补建（ID 冲突时生成新 ID） |
| 入口节点 | 随宏插入；**宏的入口语义 = 成为目标图的触发面**（外部事件到来即执行，与目标图自身入口无因果链）；与目标图已有同身份入口重复时，宏入口节点不再重复创建，其下游逻辑**自动接到目标图已有入口**上（粘贴同规则）；宏可含多个入口，各自独立触发。**校验兜底**：手改文档等路径带入同类型重复入口时报 `entry.duplicate` error（指明节点、给出修法），不阻断保存——重复消解优先在产生源头（插入/粘贴合并）完成，而非事后报错锁保存 |

变量的"同名复用"同时是**参数注入机制**：宏内刻意使用与目标图一致的全局变量名（如 `技能等级`），插入后自动接上目标图的变量。

### 3.3 零引擎改动

插入产物是普通节点/连线/变量，校验、执行、序列化路径全部复用现有机制。服务端引擎（engine/go/blueprint）零改动；Go 侧仅：引用查找把 `.obpm` 与 `.vgf/.obp` 同级扫描（不留盲区）、打开对话框增加筛选、桌面校验器新增 `entry.duplicate` 兜底规则（见 3.2）。

## 4. 使用流程

```
【创建】目录右键 → 新建宏（.obpm）→ 命名（建议 宏_<业务>_<行为>）
【编辑】双击打开，从入口节点开始搭逻辑；顶部放注释便签写用途/输入/作者
【复用】三选一：
   ① 模块库「宏/<父目录>」分类 → 双击 → 插入当前图中心（单击仅选中条目，与函数一致）
   ② 模块库拖拽宏条目 → 插入到画布指定位置
   ③ 文件浏览器右键 .obpm → 作为宏插入当前图
【演化】插入后自由修改，与源文件再无关联
```

### 约定（零强制的最佳实践）

- 宏文件集中放 `vgf/macros/`，子目录即模块库分类（`macros/buff/` → 分类「宏/buff」）；
- 命名 `宏_<业务>_<行为>.obpm`；
- 宏内**私有**变量加前缀 `宏名_` 防止意外同名合并；**刻意注入**的变量用与目标图一致的名称。

## 5. 技术实现

### 5.1 架构

纯前端功能（App.vue + createEditor.ts），Go 侧仅两处枚举调整。

```
触发（右键菜单 / 模块库条目）
   ↓
App.vue: insertMacroByPath(path, position?)
   ↓ platform.openGraph(path) 读文件（JSON）
   ↓ isNativeGraphDocument 校验（非原生文档拒绝）
   ↓
createEditor.insertGraph(document, position, label)   ← 核心合并管线
   ├─ 落点归一化（源包围盒左上角对齐落点，宏源坐标不影响插入位置）
   ├─ 变量合并（remap 表 + 补建 + onVariables 同步）
   ├─ 节点复制（复用粘贴管线：createRestoredNode / applyNodeProperties /
   │          setControlValues / 入口防重 / variableId 重映射）
   ├─ 连线重建（旧ID→新节点映射；重复入口重映射到目标图已有入口）
   ├─ 来源注释框（「宏：文件名」自动包裹插入块，见第 6 章）
   └─ refreshPortStates + 单步 undo（mutate 事务）
```

### 5.2 改动清单

| 位置 | 内容 |
|---|---|
| `frontend/src/editor/createEditor.ts` | `insertGraph()` 合并管线（落点归一化、变量合并、入口重映射、来源注释框）；`paste()` 入口重映射同规则；handle 接口 `insertGraph` |
| `frontend/src/App.vue` | `isMacroSourcePath`（.obpm）、`insertMacroByPath`（非原生文档明确拒绝提示）、`insertMacroFromContextMenu`、`createMacroAtDirectory`（默认名 `宏_`）、`macroModuleItems`（工作区树收集 .obpm，分类=父目录名）、模块库并入 `filteredModuleItems`、`addModuleItemAt` 宏分支、模块库宏条目右键「插入到当前图/编辑宏」、目录右键「新建宏」 |
| `frontend/src/editor/types.ts` | `NodeKind` 增加 `'macro'` |
| `app.go` | `FindNodeReferences` 扫描 `.obpm`；`graphFilters()` 增加 `.obpm` 筛选 |
| `core_graph_analyzer.go` | `entry.duplicate` 重复入口兜底校验（error 不锁保存，附测试） |

### 5.3 已知边界（v1）

- 宏中的**注释便签与分组不随复制**（只复制节点/连线/变量）；插入时会**新自动生成**一个带来源标签的注释框（第 6 章），与"源文件里的注释头"是两回事，后者仅作阅读说明；
- 仅接受**原生 `.obpm`**（内容非原生文档时状态栏明确拒绝）；legacy `.vgf` 想做宏：打开后**另存为 .obpm**（另存对话框已含该类型），无需手工改扩展名；
- 宏不支持签名参数表——变量同名复用是当前唯一的"参数"机制。

## 6. 插入后的显示设计

### 6.1 虚幻的显示方式与前提

UE 蓝图宏在图中显示为**单个节点**（展示宏的输入/输出引脚），双击打开宏的内部图单独编辑。这一显示成立的前提是**编辑期引用**：节点指向宏库定义，改宏库全处生效，展开编辑的永远是"那一份"定义。

### 6.2 方案对比

| 方案 | 描述 | 评价 |
|---|---|---|
| A. 裸铺开（v1 初版） | 节点直接铺进画布 | 诚实于复制语义，但无来源标识、无整体性 |
| B. UE 式单节点 | 宏实例=一个容器节点，双击下钻编辑 | 显示最像 UE，但需要嵌套子图模型（文档分层/引擎摊平/下钻编辑/作用域），工程量大；且与复制语义冲突——下钻改的是副本还是源？UE 靠引用回避，我们没有引用 |
| **C. 铺开 + 来源注释框（采用）** | 节点铺开 + 自动包一圈「宏：来源名」注释框 | 视觉语义明确：**宏=一块带框可整体拖动的整体 vs 函数=一个点**；来源可辨识；框内节点仍可就地修改（复制语义不变）；复用注释框"拖框带动框内节点"的既有机制，零引擎改动 |

### 6.3 行为细节

- 注释框标题 = 源文件名（去扩展名），插入时自动按节点包围盒生成（内边距约 24/34px）；
- 拖动注释框 → 完全在框内的节点整体跟随（注释框既有机制）；
- 删除注释框不影响节点（Delete 删框留节点，与 UE 注释框一致）；
- 用户可以随意改掉/删掉这个框——它只是视觉辅助，不是数据结构的一部分；
- 升级路径：若将来需要 B（单节点容器），C 的注释框可作为平滑转换的视觉锚点。

## 7. 与函数流程的一致性对照

| 环节 | 函数 .obpf | 宏 .obpm | 一致性 |
|---|---|---|---|
| 新建 | 目录右键「新建函数」，prompt 命名，预置入口/返回节点 | 目录右键「新建宏」，prompt 命名（默认 `宏_` 引导命名约定），空白（入口类型是业务选择，不预置） | ✅ 入口一致；差异合理 |
| 新建后 | 不自动打开，双击进入编辑 | 同 | ✅ 一致 |
| 打开/编辑 | 双击打开函数图（签名/函数面板） | 双击打开为普通图（格式一致，无特殊面板） | ✅ 一致 |
| 保存 | Ctrl+S 存回 .obpf；另存默认 .obpf | Ctrl+S 存回 .obpm；另存对话框含 .obpm 筛选、默认名保留扩展名 | ✅ 一致 |
| 使用 | 模块库函数分类 → 点击/拖入 = 建调用节点 | 模块库「宏/目录」分类 → 点击/拖入 = 整块插入 | ✅ 对称 |
| 条目右键 | 编辑函数 / 编辑函数注解 / 查找所有引用 | **插入到当前图 / 编辑宏**（复制语义无"引用"可查，故无引用项） | ✅ 语义对齐 |
| 分类来源 | functionCategory 元数据字段 | 所在子目录名 | 差异：宏零元数据，目录即分类 |

结论：创建、编辑、保存、使用四段主流程与函数完全对齐；差异点（不预置终端节点、目录即分类、右键无引用查找）均源于复制语义与零元数据的设计决策，非遗漏。

## 8. 演进路线（触发条件驱动，不预先建设）

| 触发条件 | 演进项 |
|---|---|
| 宏需要显式输入参数 | 文档内增加宏签名元数据（扩展名已有，加字段即可） |
| 需要追溯"哪些图插过这个宏" | 插入时在节点 properties 记录来源宏路径 |
| 双击 .obpm 默认动作改为"插入" | 文件关联/打开行为定制 |
| 策划反馈找宏太远 | 已由模块库分组解决；可再加收藏 |

## 9. 测试与验收

- 自动化：前端 19 套件（含宏接线结构断言）、Go 全量测试通过；
- 手动验收清单：
  1. 目录右键新建宏 → 出现 .obpm → 模块库出现「宏/…」分类；
  2. 编辑宏（入口+节点+私有变量）保存 → 目标图点击插入 → 节点/连线/变量齐备、状态栏提示复制语义；
  3. 目标图有同名同类型变量 → 插入后复用（不重复建）；无 → 自动补建并出现在变量面板；
  4. 插入后改源宏 → 目标图不受影响；插入物可一步撤销；
  5. 目标图已有同身份入口再插入宏 → 宏入口不重复，其下游逻辑接到已有入口（粘贴同规则）；
  6. 插入块被「宏：文件名」注释框包裹，拖框整体移动、删框留节点；
  7. 手工构造重复入口的文档 → 校验报 `entry.duplicate`（error、不锁保存）；
  8. 引用查找能命中宏文件内的节点类型。
