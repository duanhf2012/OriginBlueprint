# 蓝图宏（Macro）设计文档

> 版本：2.0（引用模型；v1 复制模型已于本版移除，不做兼容迁移——旧引用图请重新插入宏）
> 状态：已实现并交付（编辑器 + Go 编译库 + 热更）

## 1. 概述

**宏 = 引用语义的可复用逻辑块。** 把一段从入口节点开始的完整蓝图逻辑保存为独立的 `.obpm` 文件（创建时分配稳定宏 ID），在其他蓝图中**插入引用**：引用图只保存 `macroRefs[]`（宏 ID + 外框 + 边界连线），**不复制任何节点/连线/变量**；宏内容始终以 `.obpm` 源文件为准。

解决的核心问题：**多处业务共用同一套逻辑，希望统一维护、改一处全生效**——这正是 v1 复制模型被推翻的原因（复制后源宏修改无法传播到已插入的图，传播补丁多轮失败后确认复制语义本身不适合本场景）。

与 UE 蓝图宏对齐：编辑期引用（宏库改，使用处全刷新）+ 编译期内联展开（编译产物是平铺图，运行时无宏概念）。

## 2. 与函数的分工

| | 宏 `.obpm` | 函数 `.obpf` |
|---|---|---|
| 复用形态 | 图内一块（可多入口，编译期内联摊平） | 一个调用节点（独立编译单元，调用语义） |
| 传参方式 | 变量同名同类型自动合并（编译期） + 边界连线 | 签名参数表 |
| 内容起点 | 入口节点开始的完整逻辑（入口成为宿主图触发面） | 签名 + 入口/返回节点 |
| 引用锚点 | `macroId`（UUID，创建时分配，改名/移动文件不影响） | `functionId` |
| 适合 | 整段带触发入口的逻辑复用 | 统一维护的纯函数 |

## 3. 关键设计决策

### 3.1 引用模型（核心：引用只记宏 ID）

- 引用图（`.obp`/`.obpf`）持久化 `macroRefs[]`：`{ macroId, frame, boundary[] }`——**只有宏 ID、外框几何、边界连线**。
  - `macroId`：稳定身份，解析的唯一依据。**宏名、文件路径等一切可从宏源推导的信息一律不落盘**——显示时实时解析，改名/移动文件永不过期、绝不影响引用。
  - `boundary[]`：跨宏边界连线 `{ externalNode, externalPort, macroNodeIndex, macroPort, intoMacro }`——镜像端以**宏源 nodes 数组下标**标识（源顺序稳定），`intoMacro=true` 表示外部→宏。这是引用图自己的连线数据，不是宏派生信息。
  - 宏框注释是**运行时对象**（编辑器用注释机制承载拖拽/缩放，文本「宏：当前宏名」由加载/热更时从宏源实时渲染），不进 `comments[]`。
- 宏内容**永不落引用图**：编辑器展开为只读"镜像节点"（见 §5），编译期由引擎内联（见 §6）。
- 因此：**改源宏（内容或宏名）并保存 → 所有引用图自动更新**——已打开的图立即热更；未打开的图下次打开/校验/编译时取最新；磁盘引用文件无需任何读改写。

### 3.2 扩展名 `.obpm`：纯身份标签

- 格式与 `.obp` 完全一致（同一 GraphDocument 契约 + 顶层 `macroId` 字段），扩展名只承担身份识别；
- 家族对称：`.obp` 图 / `.obpf` 函数（f）/ `.obpm` 宏（m）/ `.obproj` 工程；
- 收益：模块库归类（「宏/<父目录>」）、右键菜单、文件对话框筛选不依赖目录位置。

### 3.3 宏名与分类（均独立于文件）

- 宏显示名存于文档 `graphName`（与函数一致），详情面板编辑；模块库条目/宏框标签用它，文件名兜底。
- **宏分类**存于文档 `macroCategory`，详情面板可编辑（下拉已有分类 + 自由输入，同函数分类交互）；模块库归类优先用它，未设置按文件父目录名（目录即分类的既有约定），再兜底「未分类」。
- 改名/改分类/移动文件不影响引用（锚点是 macroId）；两者均为编辑器元数据，引擎仅解析容忍不消费。

### 3.4 无兼容逻辑（产品决策：宏功能未发布）

v1（复制模型）代码全链路移除：复制插入、改名/内容传播、手动同步、几何自愈，以及 `GraphDocument.macroInstances` 字段本身和引擎对它的解析容忍。宏功能未发布，不存在旧格式用户文档——含 `macroInstances` 等已删字段的文档按未知字段直接报错，不做任何迁移或兜底（含 macroId 的宏创建/保存时必分配，缺失即拒绝引用）。

## 4. 使用流程

```
【创建】目录右键 → 新建宏（.obpm，自动分配 macroId）→ 命名（建议 宏_<业务>_<行为>）
【编辑】双击打开，从入口节点开始搭逻辑；宏名在详情面板改（与文件名分离）
【复用】模块库「宏/<父目录>」点击/双击/拖入，或文件浏览器右键 .obpm「作为宏插入当前图」
       → 插入的是引用：宏框（宏：宏名）+ 框内只读镜像
【接线】外部节点 ↔ 镜像端口连线即宏边界（保存为 boundary 记录，编译期内联为普通连线）
【更新】修改源宏并保存 → 已打开的引用图立即热更；其余打开/编译时自动取最新
【移除】选中宏框按 Delete = 移除整个引用（可一步撤销）
```

**宏的整体性（交互约束）**：宏加入蓝图后不可修改、不可拆分——镜像节点不可单独选中（点击镜像=选中宏框）、不可拖动、不可删除部分结点、不可复制、镜像之间不可新建连线；框选/Ctrl+A/搜索定位都不命中单个镜像（搜索结果定位到宏框）。仅允许两种操作：**整体移动**（拖动宏框，框内镜像跟随）与**整体删除**（选中宏框按 Delete）；外加端口级**边界连线**（这是"使用"宏而非"修改"宏）。

约定（零强制）：宏文件集中放 `vgf/macros/`，子目录即分类；命名 `宏_<业务>_<行为>.obpm`。

## 5. 编辑器实现（前端）

| 位置 | 职责 |
|---|---|
| `editor/macroRefs.ts` | **纯拆分/判定逻辑（vitest 覆盖）**：`splitSnapshotForPersistence` 把编辑器快照拆成持久化形态——镜像节点剔除；单端镜像连线→boundary（方向按 intoMacro）；双端镜像连线丢弃（宏内部连线展开时按源重建）；**未展开引用保留原 boundary**（防加载后立即保存丢数据）；分组 nodeIds 剔除镜像 id |
| `editor/createEditor.ts` | 引用状态（macroRefs + 镜像 id 映射）；`insertMacroRef`（登记引用+建镜像+画框，单步撤销，重复引用定位已有框）；`buildMacroMirrors`（按源顺序建只读镜像+重建宏内连线+重接边界，跳过节点记空位保持下标对齐）；`refreshMacroRef`（热更重建，外部真值不进撤销历史）；`expandMacroRefsInternal`（加载后按磁盘源展开；未找到画「宏：未找到」框并保留引用）；**整体化交互**（`setupMacroMirrorInteraction` 捕获阶段拦截镜像 pointerdown——点击=选中宏框，阻断单独选中/拖动；框选/Ctrl+A/搜索定位跳过镜像）；删除=选中宏框整体移除（可撤销）；镜像之间新建连线被拒绝并提示去源宏修改 |
| `editor/document.ts` | `MacroRefSnapshot`/`MacroRefBoundary` 契约；`NodeSnapshot.mirrorMacro`（编辑器内部标记，不持久化） |
| `App.vue` | 宏源解析器 `resolveMacroById`（扫描工作区 .obpm 按 macroId 匹配，按路径缓存）注入编辑器；`insertMacroByPath`（确保宏身份后插引用）；`propagateMacroUpdate`（宏保存/改名后刷新活动引用图与标题缓存）；`ensureMacroIdentity`（旧宏无 macroId 时补发并写回源文件）；宏保存时 `documentWithFunctionSignature` 保证 macroId 稳定注入 |
| `BlueprintNode.vue` | 镜像视觉：虚线边框 + 「宏」徽章 + 内联控件锁定（pointer-events: none）；连线端口仍可交互 |

镜像节点特性：**不可单独选中**（点击镜像=选中宏框；框选/Ctrl+A/搜索定位跳过镜像，搜索结果定位到宏框）、不可拖动（只能拖宏框整体移动）、不可删除部分结点（Delete 只作用于宏框=整体删除）、不可编辑值、不可复制；镜像之间不可新建连线；位置不持久化（每次展开按源布局重排，宏框位置保留）。

## 6. 编译期内联（Go 引擎）

入口：`Blueprint.Init/HotReload` → `loadGraphDir`（`engine/go/blueprint/loader.go`）

- `.obpm` 纳入图目录扫描；每个 `.obpm` 按其 `macroId` 进入宏索引（**重复 macroId → 冲突错误**，指明两个文件）；`.obpm` 自身也按普通图独立编译（校验宏内容）。
- 转换前 `expandMacroRefs`（`engine/go/blueprint/macro.go`）就地展开每个引用：
  - 节点全部内联，ID 前缀 `macro:<refIndex>:<macroId>:` 防冲突；
  - **变量同名同类型复用宿主定义**，缺失按源定义补建（ID 同前缀），`properties.variableId` 重映射；
  - **同身份入口（同入口 class）去重合并**：宏入口不重复创建，其下游连线接到宿主已有入口（判定用编译器同款 parseEntranceClass，口径一致）；
  - **同一宏每图仅可引用一次**：编辑器重复插入会定位已有宏框；引擎对手工重复引用明确报错（入口合并会使共享入口的 exec 出口出现多个后继）；
  - 宏内部连线随节点重映射重建；`boundary` 记录转普通连线；
  - **嵌套宏递归展开**，macroId 链检测循环引用（自引用报 cyclic）；
  - 宏未找到 → parse 阶段报 `macro <id> not found`（含引用文件路径）。
- 展开后 `MacroRefs` 清空，`graphDocumentToConfig` 只见平铺文档；带未展开宏引用直接调 `ParseGraphConfigJSON` 显式报错（拒绝静默丢宏逻辑）。
- **热更（服务器）**：`HotReload` 重读目录重编译 → 宏修改对所有引用图立即生效，已有实例下次 Do 即新行为（`TestMacroRefHotReloadTakesEffect`：宏常量 31→77，同一 graphID 输出 32→78）。
- **桌面校验沙箱**（`engine_validation.go`）：`copyValidationMacroClosure` 按引用闭包拷贝 `.obpm` 进沙箱（含嵌套传递）；当前文档自身是宏源时参与解析环，循环由引擎报告；`.obpm` 纳入 fallback 定义扫描与相对路径白名单。
- 引用图必须保存为 `.obp`：`documentRequiresNativePersistence` 对含 macroRefs 的文档返回 true（legacy .vgf 导出无法承载引用）。

## 7. 演进路线（触发条件驱动，不预先建设）

| 触发条件 | 演进项 |
|---|---|
| 宏需要显式输入参数 | 文档内增加宏签名元数据（扩展名已有，加字段即可） |
| 需要可视化"哪些图引用了此宏" | 引用查找按 macroId 反向扫描（当前 FindNodeReferences 按节点类型扫 .obpm） |
| 双击宏框直接进源宏编辑 | 详情面板已有「打开源宏」（实时解析路径），双击直达可后补 |

## 8. 测试与验收

- **引擎（Go）** `macro_ref_test.go`：内联后宏入口/边界连线可执行；热更生效；宏缺失报错；重复 macroId 冲突；同身份入口合并（节点数与单入口断言）；变量同名复用+私有补建（断言复用宿主 ID 与前缀新 ID）；嵌套宏递归展开；自引用循环检测。`parser_hardening_test.go`：macroRefs 严格解析容忍 + 单文档入口拒绝未展开引用。`macro_instance_exec_test.go`：摊平形态执行器行为（宏入口触发/外部边界驱动）。
- **桌面（Go）** `app_test.go`：引用宏的图校验通过（宏闭包拷贝进沙箱、无 engine 议题）；宏缺失时校验报错并指明 macroId。
- **前端（vitest）** `macroRefs.test.ts`：boundary 方向生成、空位下标不产生记录、未展开保留 boundary、分组剔除镜像、同宏多引用归属、孤儿镜像防御、hasMacroRef 判定。
- **前端（layout 套件）**：编辑器/持久化源码级断言（insertMacroRef/splitSnapshotForPersistence/refreshMacroRef、删除不变式等）。
- 手动验收清单：
  1. 新建宏 → .obpm 带宏 ID；模块库出现「宏/…」分类；
  2. 目标图插入宏 → 只写 macroRefs，保存后文档无宏节点/变量；
  3. 框内镜像只读（控件锁定、不可复制），点击镜像选中宏框而非镜像；框选/Ctrl+A 不命中镜像；外部节点可连镜像端口，保存重开边界保留；
  4. 改源宏内容保存 → 已打开引用图立即热更；未打开图打开时取新内容；执行/校验采用新内容；
  5. 改宏名 → 模块库、宏框、详情面板同步；文件名/路径随意改，引用不受影响；
  6. 拖宏框整体移动、框内镜像跟随；选中宏框 Delete 整体删除且可撤销；单独 Delete 镜像/框选后 Delete 均不删宏；
  7. 删宏源文件 → 框显示「宏：未找到」，校验报 not found，引用与边界记录不丢；
  8. 引用图另存为 .vgf 被阻止（必须 .obp）。
